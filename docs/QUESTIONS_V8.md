一覧は `data/photo_quiz_v8.json`。画像を用意したら、各問題の `media` に次を書き、`status` を `approved` にする。
`asset_path`（例 `assets/photo/img-0001.webp`、答えがわからない名前）・`source_page`・`author`・`license`・`license_url`・`attribution`・`alt_text`（答えを書かない）。
ビルドは、ファイルが実在し、`status: approved`・`license`・`attribution` がそろった問題だけを「写真クイズ」ジャンルに入れる。

画像の権利について：Wikimedia Commons の画像はファイルごとにライセンス・作者・表示義務を記録する。人物写真・テレビの場面写真・企業ロゴは、権利者の許可やブランドの利用規定を確認するまで入れない。写真から人物名をAIで推測して答えにしない。

## 次に問題を足すとき（例：1,000問）
1. 元データを同じ形式（`id, category_id, category, group, difficulty, question, options[4], correct_index, answer, explanation, media, review_status`）で用意する。
2. 新しい `category_id` があれば `tools/build_questions.py` の `MAP` と `NEW_GENRES`（とグループ）に足す。
3. ゲームを `?debug=1` で開き、`__qdump()` の結果を `qdump.json` に保存する（いまある問題との重複チェックに使う）。
4. `python3 tools/build_questions.py 元データ.json qdump.json data/photo_quiz_v8.json` を実行。重複・形式エラーは `questions_v8_rejected.json` に出る。
5. index.html を作り直し、テスト（`k8q.js` など）を通してから公開する。

## 公開の手順（いまある機能を壊さないために）
1. 作業は `v8-questions` ブランチで行う（いまの main は変えない）。
2. テストがすべて通ったら、GitHub でプルリクエストを作り、内容を確認してマージする。
3. GitHub Pages は main を公開しているので、マージ後1〜2分で反映される。戻したいときは、そのマージを revert すれば前の版にもどる。

## 注意
- 追加データは「草稿」「旧版から引継ぎ・要確認」の状態です。政治家・金利・制度・作品の細部など、公開前に事実の確認をおすすめします。
- 作品ファン向け（ONE PIECE・鬼滅の刃・VIVANT・嵐）は文字のクイズだけで、画像・ロゴは使っていません。
