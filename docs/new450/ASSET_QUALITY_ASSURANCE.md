# 元画像を壊さないための視覚QA手順

## 現在の到達点
- 21枚の大きいPNGシートから、合計450の「S1・S2・S3が横並びの3連絵」を座標で切り抜いた。
- 各3連絵を機械的にさらに切り出して1350のWebPを生成。**AIで新しいイラストを生成したわけではない**。
- ただし3連絵はレイヤーで独立しておらず、S2やS3が横へはみ出す箇所もある。自動切り出しの際に、頭・腕・飾り・羽の一部が欠けたり、前後の形態や金色の星が混入する可能性がある。
- 元絵の解像度は各3連絵に約300〜360px、1進化形に約70〜200px程度。大きく拡大するとぼやける。**拡大で描き足していない**。

## 具体的な作業
1. このZIPを展開し、`qa/character_gallery.html` をブラウザで開く。全450系列が最初から並んでいる。検索欄で `NZ001`〜`NZ450` を確認できる。
2. 各カードの上の大きい原3連絵と、下のS1/S2/S3の切り出しを並べて、**3形態がそれぞれ完全に写っているか**をチェックする。
3. 切れているキャラは、その系列の原3連絵を元に切り出しを再作成し、同じパスを上書き。単純な縦線カットでは取れない場合、輪郭に沿ったマスク切り出しで対応する。**文字プロンプトによる描き直しはしない。**
4. 目視検査用ステータスを `needs_visual_crop_QA` → `verified` に変更。チェックした人、日付、どのファイルを修正したかを記録。
5. `produced_asset_sha256.json` のハッシュを更新し、`python tests/validate_catalog.py` で参照が欠けていないか検査。
6. 高画質の制作向けに、可能なら21枚の画像を制作した元ファイルの個別キャラレイヤー、または透過PNGの原画を確保。これがもっとも安全で高品質。

## 画像が表示されない時のチェック
- `<img src="assets/characters/NZ001/stage-1.webp">` のように直リンクする。大文字小文字を同じにする。
- `file://` から開くQA用HTMLは、JSONをfetchせずHTML内に一覧データが内蔵されている。
- GitHub Pagesではリポジトリのサブパスに注意。相対URLかビルド時のbaseURLを統一する。
- WebPが読み込めるブラウザを使用（現代の主要ブラウザは対応）。古いブラウザ互換が必要ならPNG版も個別用意。
