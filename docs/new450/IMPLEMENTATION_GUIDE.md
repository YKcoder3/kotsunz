# コツンズ450キャラ導入：実装・初期化・品質管理・公開ガイド（v3）

## 目的
ユーザーの新しい画像シートのみを新キャラクターの美術的な原典とする。過去のキャラ名／キャラ絵／レアリティ・設定を引き継ぐのではなく、**ゲームの回答・早押し・対戦・育成・進化の機械的ルールを維持**して全面リスキンする。提出物はコツンズ本体に適用されていない画像・JSON・仕様・参考テスト。実装はClaudeが本番コード調査後に行うこと。

## 正規のデータ

|ファイル|役割|
|---|---|
| `data/characters_450.json` | 新450ファミリーの属性、レア度、名前、物語、得意・苦手、画像、ID |
| `data/forms_1350.json` | 3進化形態の画像パス・段階名・スキル解放 |
| `data/special_skills_450.json` | 各新キャラ固有必殺技2案、役割と解放段階 |
| `data/special_config_new450.json` | 3系統必殺技とミラー・ゲージ・補正・初期化の最新ルール |
| `data/asset_manifest_450.json` | 21元画像→450枠→1350画像の一意の対応表 |
| `data/images_matching_450.csv` | 同じ対応表の人間確認用CSV |
| `data/source_sheets_21.json` | 元の21 PNGのファイル名・原画像SHA-256・画像サイズ・行列 |
| `data/produced_asset_sha256.json` | 生成した全1800 WebPのチェックサム |
| `assets/families/` | 3形態をひと枠に保った450枚の原典参照画像（再描画なし） |
| `assets/characters/NZxxx/stage-*.webp` | 自動切り出し済み1350枚の実画像（要QA） |
| `qa/character_gallery.html` | オフラインでも開ける、画像とIDの確認画面 |

## IDと名前の考え方
- `NZ001`〜`NZ450` は旧 `K001`〜と別名前空間。改名してもIDは変更しない。
- `name`, `stageNames`, `lore`, `personality`, `catchphrase`, `quizFlavor` は今回 **画像の特徴を参考に新規提案**。画像ZIPから抽出された公式名称ではない。ユーザー編集で品質を上げる。
- 得意と苦手は意味的な新案。マスター上の「地理」「食べ物」「宇宙・科学」等は正規化候補ラベルであり、実装時はゲーム本体の実際のジャンルIDに合わせる。未定義を勝手に作らない。
- 参考資料の6属性はそのまま維持。属性有利はゲージ増加に集約し、旧常時ダメージ倍率を重ねない。
- レア度は進化とは独立。ガチャ排出確率は添付旧仕様から受け継いだ暫定値であり、キャラリスト内の件数比とは違う。

## 差し替え作業
1. 現行リポジトリのキャラ関連のID、KMASTER、K_GOOD/K_WEAK、gacha, dex, evolved forms, gameSession, UI、ローカルストレージを調査。
2. 新データを読み込むアダプタを作成し、**旧キャラマスター・旧ID・旧セーブを一掃**。保存スキーマとカタログ世代を上げ、初回起動時に一回だけコツンズ旧プレイヤーデータをリセットして新規保存状態を作る。データ移行はしない。画像ファイルの存在と大文字小文字を検証。URLをfetchする場合のGitHub Pagesのベースパスに注意。
3. 既存の生成SVG/CSS/絵文字プレースホルダより画像アセットを優先。画像が壊れた場合だけ控えめなフォールバックを表示し、欠けたファイルを黙って無視しない。
4. 画面上の全キャラ（トップ、ガチャ、図鑑、進化、詳細、バトル、報酬、共有）をマスター由来にし、表示用にランダムで別のキャラ画像を当てない。
5. キャラ絵の縦横比保持：`object-fit: contain;`、`max-width:100%` を基本にする。意図せず人物を切る `object-fit:cover` は避ける。
6. サムネイルが見切れる場合、勝手にAIでリメイクせず、該当ファミリー3連画像と元シート番号から再切り出しする。
7. ゲームを動かしながら画面ごとのスモークテスト、キャラ450種の全画像リンク、進化パス、発動条件を検証。

## 初期アートの制約
元資料の画像は、1PNGにつき複数キャラ、1枠につきS1・S2・S3の3連絵。人物ごとの原画レイヤーや独立PNGは**もともと存在しない**。本パックのS1/S2/S3は画素を切り出しただけで、AIによる再生成はしていない。したがって「進化ごとの画像が元通りであるか」は `qa/character_gallery.html` で検査が必要。**品質未確認の形態があれば、正式公開には使わず原画を基準に再マスク／切り出し。** WebPは圧縮画像なので厳密な画素一致は原PNGではなくマスターの画像モチーフ・形状に対して行う。

## 旧データの全初期化（旧セーブ移行をしない）
- ユーザーの最新指示により**旧セーブを完全に初期化**する。旧 `K001` と新 `NZ001` は無関係なので、旧キャラ所持分の移行・交換・アーカイブ・プレゼントは実装しない。
- 名前/ユーザーID、キャラの所持・レベル・進化・図鑑・育成資源、コイン・ガチャ履歴・天井、戦績等の**コツンズ固有のプレイヤーデータはすべて初期値に戻す**。過去データの保管/移行/補償はしない。
- **新450世代の最初の起動時に一度だけ**、実リポジトリの利用保存先を棚卸しして、該当するコツンズ旧データのキー・ストアを削除した後、新スキーマを作成。完了マーカーを記録して再起動では繰り返さない。
- `localStorage.clear()` 等の無差別全消去は禁止。他のアプリや同一オリジンの無関係なデータを巻き込まない。複数タブ・旧キャッシュ・古いオンライン通信・インポートで旧キャラが再出現しないことをテスト。
- 初回起動前の更新告知「新キャラ導入により以前のプレイヤーデータは初期化されました」を明示。ゲームそのもののコード・問題集・ジャンル・対戦ルールを削除しない。
- 詳細手順・初回起動の受け入れ試験は `docs/RESET_POLICY_V3.md` を最優先とする。

## UIテスト
- 450件図鑑の最初・途中・最後に異なるキャラが出る。見た目とキャラ名が一致。
- `NZ001-S1`と`NZ001-S2`と`NZ001-S3`がそれぞれの画像を参照し、他家族の画像を使わない。
- **初期化後の新データ**は保存・再読み込み・復元後にも同じ進化と画像。**旧版のバックアップをインポートして旧キャラが復活する経路は閉じる**。
- サムネイル・スマホ画面・対戦画面で画像がはみ出さず、3形態を識別できる。
- 既存オンラインの部屋コード・3.2秒前後のジャンル告知・10秒回答・ホスト判定等は実コードを根拠に維持する（旧資料の数値を強制しない）。
- 権利・商標・画像の検査は `docs/RIGHTS_AND_RELEASE_CHECKLIST.md` の手順で必ず実施。クリア後は `scripts/approve_release.py` で公開フラグを更新し、**一般公開まで進める**（未確認の権利を推測で承認しない）。
