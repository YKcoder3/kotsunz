# コツンズ旧データ全初期化ポリシー v3（Claude実装仕様）

## 目的
新画像450系列/1350形態の正式採用に合わせて、旧キャラと旧プレイヤーデータを**全廃**しつつ、ゲームの仕組みを維持して新規スタートする。ユーザーは旧プレイヤーデータの保全・交換・補償を希望しない。

## 初期化対象
実リポジトリで保存キーと保存先を特定したうえで、コツンズ固有の古いプレイヤー記録を削除：旧ニックネーム/プレイヤーID、所持キャラ・編成・図鑑・進化/育成・スキン、コイン/ガチャ/天井/素材/ミッション/実績、戦績/ランキング/クイズ履歴、進行中試合・ゲージ・通信再接続状態、旧カタログのキャッシュ/インポートデータ。旧キャラ `K001...`、旧50/500系統を表示・参照するマスター/画像/フォールバックも削除。

## 絶対に消さないもの
4択・正誤・出題バンク・ジャンル/問題の追加機能・早押し順位・回答制限時間・CPU/オンライン・部屋コード・ガチャ/育成/進化の**機能そのもの**。コツンズと無関係なブラウザ保存領域や同じオリジンの他サービスのデータ。

## 実装手順
1. 開発ブランチで `localStorage`、`sessionStorage`、IndexedDB、Cache Storage、Service Worker、実際にあるリモートDB/APIの保存箇所を列挙。削除する具体的なキー/ストアを特定する。
2. `new450-v2-reset` 世代の初回ロードに限り、旧コツンズデータを削除。移行/旧IDマッピングをせず、**新規初期状態**を構築。旧データを保管するアーカイブや補償は作らない。
3. 新状態の保存が成功した後だけ、`kotsunz_catalog_epoch_new450_v2` 等の完了マーカーを保存。失敗時再実行、複数タブの同時実行、更新中のリロードも安全な作りにする。
4. 2回目以降の起動では初期化せず、新キャラ・コイン・進化/戦績を正しく保持。
5. 旧タブ、旧キャッシュ、旧バックアップのインポート、古いオンラインクライアント経由で旧カタログIDが復活しないよう、セーブ/通信の世代IDを検証して拒否・再読込させる。
6. 更新時の案内文：「新キャラクターへのリニューアルに伴い、これまでのコツンズのプレイヤーデータ（キャラ・コイン・戦績など）は初期化されます。新しいキャラクターで最初からお楽しみください。」を初回に表示する。文面は実際の実行タイミングに合わせる。

## 必須テスト
- 初回ロード：旧所持・旧通貨・旧戦績・旧ニックネーム・旧IDが残らない。
- 新450でプレイ→ガチャ・進化・戦績を保存→再読込：**新しいプレイ記録は維持**。
- 二重タブ・中断・旧バックアップ・旧タブでも旧データが混ざらない。
- `localStorage.clear()` のような無差別消去を使わず、別アプリの保存に触れない。
- クイズ問題、4択、早押し順位、CPU、オンライン対戦、ルームコード、ガチャ/育成/進化の機能を維持。

## 最終公開までの作業
初期化の確認が済んだら、別資料 `RIGHTS_AND_RELEASE_CHECKLIST.md` に基づき権利・商標・画像品質・ゲーム動作を確認し、**問題を解消したうえで一般公開まで進める**。ユーザーは公開を希望しており、今回の初期化はその前提作業。調査できない権利の出所を憶測で「確認済み」としてはならない。
