# 【Claudeへ貼り付ける最新版指示】コツンズ 新450キャラ導入・旧データ全初期化・確認後一般公開（v3）

あなたは既存のコツンズ（YKcoder3/kotsunz）の実装担当です。ユーザーは新キャラクター版の**一般公開を希望し、必要な確認が終了した時点での公開も依頼済み**です。単に「公開前のチェックが必要」と書いて終了せず、実施できる調査・修正・テスト・公開まで完了させてください。ただし、証拠のない権利クリアを勝手に認定してはいけません。必要な画像制作履歴・許諾資料が欠ける場合だけ、欠けている証拠を具体的に列挙して開発者に確認してください。権利リスクのある画像を未確認のまま公開しないでください。

## A. アプリの方針（最優先）
- 公式キャラクターは、このパックの **NZ001〜NZ450（各S1/S2/S3、1350形態）だけ**。ユーザーの原画像から切り出したWebPをそのまま使用。コードで再描画したり別の見た目にしたりしない。画像ID対応表も使う。
- 旧50・旧500系列の名前、絵、物語、図鑑、ガチャ、旧特技、旧キャラIDは本番のキャラとして一切残さない。参考用の文書はロジック参照専用。
- **旧プレイヤーデータは丸ごと初期化**。ニックネーム/ID/キャラ/コイン/戦績/図鑑/経験値/進化/所持品/ガチャ/ミッション/ランキング等は継承しない。旧データの交換・補償・アーカイブ不要。
- 初期化は新450版に切り替わった初回起動時に**一度だけ**実施。以後の新データはリロード後も保持。保存場所を実コードで調べ、コツンズ固有の保存キーだけ削除（`localStorage.clear()` 禁止）。古いタブ/端末/バックアップから旧IDが戻らないよう版判定。初回の案内も表示。
- 4択クイズ、早押し順位、問題バンク、CPU、オンライン対戦、部屋作成/コード参加、ガチャ・育成・進化のゲームルールは**維持**し、キャラ内容と必殺技処理だけ更新する。

## B. 最新必殺技ルール
- 全員ゲージ1本（0〜100、開始10、小25/中55/大90）、1問で選択可能な技1件だけ。固有必殺技はキャラと進化・レアリティにより1〜2個。
- Attack: **その問題で1位正解**した時だけ発動/消費。
- Defence: **不正解・時間切れ・早押し負けでも防御**。有効宣言時に消費し、問題中に受けるダメージから減らす。防ぐ相手の攻撃が0でも宣言は消費する。
- Recover: **正解すれば順位を問わず回復**、1位なら追加回復。間違いなら不発・消費なし。低HP救済や小さなオーバーヒールシールドを設計通り維持。
- Mirror Defence: 実際に防いだダメージだけ記録し、限定的に相手へ分配。架空ダメージの反射・無限反射はしない。
- PvPの公平性を重視し、レア度や進化で理不尽な大差を付けない。詳細は `docs/BATTLE_SKILLS_V4.md`。

## C. 著作権・商標・画像品質を**実際に確認して、問題が解決したら公開する**
1. **権利の出所**: 元の21画像シートについて、作成者・生成/制作手段・利用規約・商用利用と再配布の権限・第三者素材の混入を調べて証跡を記録。ZIP自体にはこれらの証明がないので、推測で「権利確認済み」と書かない。開発者提供の制作履歴や利用許諾が必要なら具体的に要求。
2. **類似性**: 450系列を画像ギャラリーで見て、既存アニメ・漫画・ゲーム・企業マスコット等の独自表現・ロゴとの類似/依拠リスクを調査。引っかかったものは理由/比較対象/対処を記録し、必要なら許諾取得またはデザイン差し替え（勝手なAI全件再描画はしない）。外部検索で完全な非侵害の証明ができると誤認しない。
3. **商標**: 「コツンズ」「KOTSUNZ」、新規450キャラの名前と読み、主要な必殺技名について、J-PlatPat等で同一・類似の商標と該当する商品役務を調査。懸念は改名や専門家確認で解消。検索実施日・結果・調査範囲を残す。
4. **画像品質**: 450系列×S1/S2/S3全件の対応・欠け・混入・余白・スマホでの表示を確認して修正。`qa/character_gallery.html` と原画の3連絵を照合し、全件確認の記録を残す。
5. **実装・公開**: 上記4分野の懸念解消、ゲーム回帰テスト合格、旧データ初期化テスト合格を確認したら、`scripts/approve_release.py` で公開承認をデータへ反映（`publishable: true`、レビュー記録の更新）。**ここで別途もう一度「一般公開していいですか」と承認を取り直さず**、可能なリポジトリ権限・デプロイ手段で GitHub Pages まで反映し、URLとテスト結果を報告。公開権限がない場合はコミット/PR/具体的手順を提出して「公開済み」とは主張しない。
6. **差し止めは一時的な未完了ステータス**: 初期データの `publishable:false` は「権利と品質の未確認」であり永続的な公開禁止の指定ではない。**チェック完了後、公開可能に更新することが必須の作業**。ただし証拠が欠けたまま true にしない。
