# 1. データ構造 — 500キャラ × 3進化 = 1500形態

## 1-1. IDとマスター
- キャラID `K001`〜`K500` は**固定**。最初のK001〜K050は旧アプリで既に存在するため**絶対に変更しない**。
- 形態IDは `${characterId}-S1|S2|S3`。ステージはコレクションの形態であり、同一キャラの複数個体の管理とは別。
- `data/characters_500_full.json`: 名前、レア度、属性、得意/苦手ジャンル、物語、キャラクターDNA、口癖、反応アニメ、3形態のデザイン。
- `data/special_skills_500.json`: 1キャラに1件、`skillId`, `family`, `costs`, `animation`。実際の威力は `special_config_v3.json` のファミリー別ルールのみを参照。
- `data/forms_1500.json`: ユーザーが見つけた形態、正式画像の未完成状態、SVGパス。
- どのJSONでも `strength` や `onePoint` 等をユーザー表示のメイン情報として使用しない。

## 1-2. 進化
- 1体目：S1入手。
- 同じキャラのS1が合計3体になったら、任意の1体を残して2体を素材に**S2へ進化**。ロック済み/お気に入り個体は素材にしない。レベルは引継ぎ。
- S2からS3はレベル20以上＋覚醒石10＋キャラ専用ミッション。S3に追加重複ガチャ必須としない。
- キャラのレア度と属性は進化しても不変。進化で必殺技固有演出と1種類の小さな威力が少し高まる。
- 同一キャラ・同一レアリティを3体入手して進化することと、違う景品の組合せを必須にすることは混同しない。実売時の景表法やライセンス審査を別途受ける。

## 1-3. レア度・ガチャ（確率は1回あたり）
| tier | rate | notes |
| --- | ---: | --- |
| おつ | 45% | はずれ扱いしすぎず、かわいいキャラを維持 |
| 普通 | 35% | 初期収集の中心 |
| レア | 15% | 少し希少 |
| スーパーレア | 4.5% | 特別な演出 |
| レジェンド | 0.5% | 収集価値と演出の最上位 |

**抽選は「レア度→有効プール内のキャラ」**の2段階。500体すべてを同時に均等排出すると特定の3体進化が困難になりすぎるため、無料デモではローテーションのピックアップ枠を設けてよい。排出対象・各確率はガチャごとに確認できるUIにする。未公開の天井を勝手に追加しない。無料コインのみ（有料決済OFF）。

## 1-4. データ移行
- 現行のブラウザ保存・引継ぎ方式を維持。バージョンを付けて必要なフィールドだけ追加。既存ユーザーの `iid / cid / st / lv / exp / found / favorite / coins` 等を可能な範囲で保持。
- 既存の `dex` のような旧保存形式が残っている場合、移行前バックアップを取り、二重変換しない。
- コラボは `C` 系IDやスキンIDを本編 `K001..K500` と別に管理し、無許諾は非公開。
- 最終形態の正式画像が無ければSVGプロトタイプを表示する。`assetStatus`だけでなく**存在するURLか**を確認するかビルドマニフェストで存在を保証。

## 1-5. 得意・苦手のID
- `data/genres.json` のキーのみ利用。キャラ個別の `genreAffinity.favorite` と `genreAffinity.weak` は重複不可。
- 属性との相性関係は `data/game_config_500.json` に定義。キャラごとの得意・苦手でクイズの正解確率が自動的に変わるわけではない。
- これらは**ゲージ獲得条件と演出**の設定で、通常ダメージの常時倍率ではない。
